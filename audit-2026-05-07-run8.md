# Protein Outfitters — Site audit, run 8 (2026-05-07)

Automated audit of `https://www.proteinoutfitters.com` for broken buttons,
links, and API endpoints. Branch on disk: `cowork-audit-fixes`. Live deploy:
`origin/main`.

This run was triggered by the **`protein-outfitters-audit`** scheduled task —
running autonomously, no user present. Per the scheduled-task contract I made
the fixes in the working tree and ran static checks; **no code was pushed to
production from this run** because the runner has no GitHub credentials. The
checklist at the bottom of this file is what's needed to ship the fixes.

---

## Methodology

1. Fetched every page linked from the homepage, then crawled their internal
   links recursively (one hop deep) — 39 HTML pages and 27 distinct API
   endpoints.
2. For every internal route, made the same request the page itself makes
   (correct method + minimum body) and recorded the status.
3. For every endpoint that returned 4xx/5xx, traced back to the JS handler in
   `deploy/api/` and looked for the failure mode.
4. Patched each issue in the working tree, ran `node --check` on every modified
   file, and re-validated `vercel.json` with `JSON.parse`.

All "tests" are HTTP probes against the live site — no headless browser, so
client-side JS interactions are inferred from source and not click-tested.

## Fixes applied (in working tree)

All fixes are on branch `cowork-audit-fixes`. Issues B/C/D/G/H were already
patched in earlier audit runs but never committed-and-pushed. Issues A/E/F/I
are new patches from this run.

### A. `/api/hardware-lead` 500 — already fixed in working tree

`deploy/api/hardware-lead.js`:
- Replaced top-level `import { sendLifecycleEmail }` with a lazy
  `await import('./_lib/email.js')` inside the side-effect block.
- Wrapped the handler in a try/catch that returns a structured JSON 500 instead
  of `FUNCTION_INVOCATION_FAILED`.

### B/C/D. Missing `/api/donation-funds`, `/api/donate-to-fund`, `/api/complaint`

The endpoint files exist in `deploy/api/` on the local branch:
- `deploy/api/donation-funds.js` — public summary + admin ledger CRUD.
- `deploy/api/donate-to-fund.js` — Stripe Checkout session for fund gifts (lazy-imports `stripe`).
- `deploy/api/complaint.js` — buyer-side complaint capture, schema in
  `api/migrate.js`.

They just need to ship.

### E/F. PDF endpoints 500 — fixed in working tree this run

`deploy/api/_lib/pdf.js`:
- `import PDFDocument from 'pdfkit'` → moved into `pdfToBuffer()` as
  `const PDFDocument = (await import('pdfkit')).default;`. This converts a
  module-init crash into a normal thrown error inside the request path.

`deploy/api/pdf/deed-of-gift.js`, `tax-letter.js`, `annual-tax-letter.js`:
- Renamed the inner handler to `_handler` and added a top-level `handler` that
  wraps `_handler` in try/catch, logs to `console.error`, and returns a JSON
  500 with `{ error, message }` instead of letting Vercel render
  `FUNCTION_INVOCATION_FAILED`.

### G. `/brand/po-favicon.svg` 404 — already fixed in working tree

`deploy/discover.html` line 8: `/brand/po-favicon.svg` → `/brand/favicon.svg`.
Confirmed the rest of the site already uses `/brand/favicon.svg`.

### H. `/policies/privacy` and `/policies/terms` 404

The HTML files exist in the working tree
(`deploy/policies/{privacy,terms}.html`, ~7.5KB each, valid HTML). They just
need to ship along with the rest of the audit-fixes commit.

### I. `/legal/privacy`, `/legal/terms`, `/privacy`, `/terms` 404 — fixed this run

`deploy/vercel.json`: added four redirects so the app-store-required URLs
resolve to the canonical `/policies/*` pages once they're deployed:

```json
{ "source": "/legal/privacy", "destination": "/policies/privacy", "permanent": false },
{ "source": "/legal/terms",   "destination": "/policies/terms",   "permanent": false },
{ "source": "/privacy",       "destination": "/policies/privacy", "permanent": false },
{ "source": "/terms",         "destination": "/policies/terms",   "permanent": false }
```

Used `permanent: false` (302) intentionally — easy to swap to first-class
routes later without leaving stale 301s in Google's cache.
