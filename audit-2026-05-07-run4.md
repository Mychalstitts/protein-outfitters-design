## Findings

### NEW — Bug 1: Reserve sheet shows per-pound rate as the share total

The homepage card correctly reads "From $1,275" for a quarter share of #214
(Hereford steer · 680 lb HW @ $7.50/lb). Tap the card → the share-picker
modal renders the three options as **`$7.5`**, **`$7.25`**, and **`$6.95`**
instead of `$1,275`, `$2,465`, and `$4,726`. The "Reserve today" total on
step 3 is then calculated as `$7.50 + $225 + $18 = $250.50` — which the
buyer would see as the price they're being charged.

Root cause in `deploy/index.html` (the dynamic listings render):

```js
data-price-q="${l.shares?.quarter?.price || 0}"   // raw $/lb HW
data-price-h="${l.shares?.half?.price || 0}"
data-price-w="${l.shares?.whole?.price || 0}"
```

The downstream sheet code (`buildShareOptions`, `setStep`) treats these as
absolute share dollars. The card itself uses `farmerRate * fractionLbs` for
display; the data attributes never got the same treatment.

**Fix applied** (`deploy/index.html` near the listing renderer):

```js
const totalQ = Math.round(Number(l.shares?.quarter?.price || 0) * hw * 0.25);
const totalH = Math.round(Number(l.shares?.half?.price   || 0) * hw * 0.5);
const totalW = Math.round(Number(l.shares?.whole?.price  || 0) * hw * 1);
return `<button class="product" data-open-sheet
    data-animal="${l.id}" ...
    data-price-q="${totalQ}"
    data-price-h="${totalH}"
    data-price-w="${totalW}">`;
```

Verified the math against the live card: 7.5 × 680 × 0.25 = 1,275 (matches
"From $1,275"). Half: 2,465. Whole: 4,726. Reserve-today summary will then
read `$1,518` for a quarter (1,275 + 225 + 18), which is the right number.

### NEW — Bug 2: Footer has no Privacy / Terms / Refunds links

Per `PROJECT_INSTRUCTIONS.md`: *"Privacy policy + Terms must be hosted on
the web and reachable in-app."* The live footer has Marketplace / For
partners / Company columns but no Legal column. The HTML files for
`/policies/privacy.html`, `/policies/terms.html`, `/policies/refunds.html`
exist in `deploy/policies/` but are not linked from anywhere on the
homepage.

**Fix applied** — added a "Legal" column to the footer in `deploy/index.html`:

```html
<div>
  <h4>Legal</h4>
  <ul>
    <li><a href="/policies/privacy">Privacy</a></li>
    <li><a href="/policies/terms">Terms</a></li>
    <li><a href="/policies/refunds">Refunds</a></li>
  </ul>
</div>
```

Also synced the existing footer label `Donation Depot` → `Producer
Partnership` to match the live nav copy (the link target `/donation-flow`
is unchanged).

### Observed but **not fixed** this run

- **Account page widgets stuck on "Loading"** — `/account` renders the
  shell but the "Active reservations" stat tiles and the "Active
  reservations" list both stay on placeholder ("___ animals", "Loading
  your reservations…"). The page calls `/api/auth/me` which was still
  pending after page load; could be a session/cookie issue or a slow API
  endpoint. Did not dig into the API layer this run — leaving for a
  dedicated sweep with logs.
- **`Reserve` button on hero with no animal selected** opens the share
  sheet *and* scrolls to the listings section, even though `state.animal
  === null` so the share grid is empty. The intended UX is probably "scroll
  to listings only, don't open empty sheet." Minor — one-line fix in the
  `open()` function (skip the `sheet.classList.add('open')` when no
  animal). Left for a later cleanup pass.
- **Discover listing cards have no photos.** Cards render the price + farm
  + species but the image area is blank. Looks like the discover renderer
  uses a different photo path than the homepage cards do. Worth a
  follow-up — the same `photoFor()` helper that the homepage uses would
  fix it.
- **Reserve sheet backdrop / page background** shows duplicated faded card
  outlines on the right side of the viewport when the sheet is open. Looks
  like an iframe/cache artifact from the screenshot tool more than a real
  CSS bug — couldn't reproduce reliably. Worth eyeballing on a real device
  before chasing it in CSS.

## How to ship these fixes

The deploy unit is `audit-fixes/protein-outfitters-design/deploy/`, which
Vercel auto-builds from the `Mychalstitts/protein-outfitters-design`
repository on push to `main`. The `cowork-audit-fixes` branch carries all
of run 2, run 3, and this run's edits.

```bash
cd "audit-fixes/protein-outfitters-design"
git add deploy/index.html audit-2026-05-07-run4.md
git commit -m "Audit run 4 — share-total math + footer Legal column"

git fetch origin main
git merge origin/main          # resolve conflicts if any (likely none)
git push origin cowork-audit-fixes

# Then either open a PR, or fast-forward main locally:
git checkout main
git merge --ff-only cowork-audit-fixes
git push origin main
```

Vercel will auto-deploy on push to main.
