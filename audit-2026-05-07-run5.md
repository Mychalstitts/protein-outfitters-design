## Findings

### NEW — Bug 1: Account hero stats look stuck on a skeleton loader when signed out

`/account` renders a dark hero card on the right with **ACTIVE
RESERVATIONS / FOLLOWED FARMS / YTD SPEND / TOTAL ORDERS**. The
initial HTML seeds each value with an em-dash (`—`) and the page
script populates them after `/api/auth/me` resolves. When the visitor
is **not signed in**, the script returns early without setting any
of the values, so the card stays on em-dashes — which read as
skeleton placeholders, not as concrete "you're not signed in" state.

Root cause in `deploy/account.html`:

```js
if (!me.user) {
  banner.style.display = 'flex';
  list.innerHTML = `…sign in CTA…`;
  return;          // ← returns before setText(...) ever runs
}
```

**Fix applied** — set the four stat tiles to concrete zeros before
the early return:

```js
if (!me.user) {
  banner.style.display = 'flex';
  // Replace skeleton em-dashes with concrete zeros so the hero card
  // doesn't look like it's stuck loading when the visitor is signed out.
  const setText = (id,v) => { const el=document.getElementById(id); if(el) el.textContent = v; };
  setText('acStatActive', '0');
  setText('acStatFarms',  '0');
  setText('acStatSpend',  '$0');
  setText('acStatOrders', '0');
  list.innerHTML = `…sign in CTA…`;
  return;
}
```

Verified locally by serving `deploy/` on `python3 -m http.server` and
re-grepping the HTML; the new comment + `setText` calls are present.

### NEW — Bug 2: Hero "Reserve" CTA opens an empty share sheet when no animal is selected

The big top-nav **Reserve** button (and the hero **Reserve →**) carry
`data-open-sheet` but no `data-animal`. When clicked the page falls
through to `open(undefined)`, which currently both opens the share-
picker sheet (with an empty share grid) AND scrolls to `#reserve`.
The user sees a half-rendered modal sitting over the listings —
dead-end UX.

Root cause in `deploy/index.html`:

```js
function open(a) {
  if (a) { /* set up animal */ }
  else {
    backdrop.classList.add('open');
    sheet.classList.add('open');                  // ← opens empty sheet
    sheet.setAttribute('aria-hidden', 'false');
    setTimeout(() => {
      document.querySelector('#reserve').scrollIntoView({behavior:'smooth'});
    }, 50);
    return;
  }
  …
}
```

**Fix applied** — when there's no animal, just scroll to the listings
and skip the sheet open:

```js
} else {
  // No animal selected — just scroll the user down to the listings grid.
  // Previously we also opened the sheet here, which left an empty share
  // picker on top of the listings. Scroll-only is the right UX.
  document.querySelector('#reserve')?.scrollIntoView({ behavior: 'smooth' });
  return;
}
```

### Observed but not fixed this run

- **Discover page footer is structurally different from the homepage
  footer.** Homepage uses an inline footer (Marketplace / For
  partners / Company / Email). Discover uses the `po-shell.js`
  generated footer (Marketplace / For partners / Help & Policy /
  Company), and Help & Policy lists FAQ + Refund policy + two email
  addresses but no Privacy/Terms link. Once the two policy HTMLs
  are merged, the shell footer should also gain a Privacy/Terms
  entry — leaving as a follow-up.

- **Producer cards all show "0 listings"** even though the API has
  three active listings. The `farm.listings_count` on the producers
  API isn't being computed from real listings — leaving for a
  dedicated data sweep, not a UI bug.

- **One listing in the API has all share prices = 0** (#2641 from
  Stitty Ranch). The homepage filters it out (`anyPrice > 0` filter)
  but the discover page renders it with a synthetic `$1.63/lb`
  (= 0 farmer rate + 1.55 platform fees + $0.08 of math drift).
  Either filter it out the same way the homepage does, or surface
  a "Pricing TBD" badge — leaving for a follow-up.

## How to ship these fixes

The deploy unit is `audit-fixes/protein-outfitters-design/deploy/`,
which Vercel auto-builds from the
`Mychalstitts/protein-outfitters-design` repo on push to `main`. The
local branch `cowork-audit-fixes` is currently +1/-4 vs `origin/main`
and carries every audit fix from runs 2 through 5. **Nothing has
been pushed in this run — the working tree edits live on disk only.**
Owner needs to commit + merge:

```bash
cd "audit-fixes/protein-outfitters-design"

git add deploy/index.html deploy/account.html audit-2026-05-07-run5.md
git commit -m "Audit run 5 — empty Reserve sheet + signed-out account hero"

# Reconcile with origin/main (4 commits diverged) before merging
git fetch origin main
git merge origin/main          # resolve conflicts if any (likely none)
git push origin cowork-audit-fixes

# Then either open a PR, or fast-forward main locally:
git checkout main
git merge --ff-only cowork-audit-fixes
git push origin main
```

Vercel auto-deploys on push to main.
