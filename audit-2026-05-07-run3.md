   `GET /api/config` returning `{"mapsKey":""}`. Without it, the
   `/api/discover-nearby` endpoint returns `500 GOOGLE_MAPS_KEY not configured`
   (fast and structured, after the run-2 timeout fix), and the
   "Discover nearby" button on `/discover` and `/map` shows nothing. Set in
   Project Settings → Environment Variables (recommend restricting the key by
   HTTP referrer to `proteinoutfitters.com` and `*.proteinoutfitters.com`).
2. **`/api/hardware-lead` underlying root cause** — local hardening means it
   now returns a structured 500 instead of `FUNCTION_INVOCATION_FAILED`, but
   the underlying module-init failure (likely `@neondatabase/serverless` or
   `Resend` blowing up under the production nodejs runtime bundle) still
   needs to be diagnosed from Vercel function logs. Once we see the stack
   trace from the new top-level guard's `console.error`, the actual fix is
   probably one missing env var or one lazy-import.
3. **`/api/checkout`, `/api/upload`** — same `runtime: 'nodejs'` failure
   pattern as `hardware-lead`. Same diagnosis path. Not patched this run to
   keep the diff small; apply the same lazy-import + try/catch pattern once
   the root cause is known.
4. **Cron jobs** — `vercel.json` registers `/api/email-tick` (daily) and

## How to actually deploy

The scheduled task can prepare the fix but cannot push it. The sandbox can't
remove the stale `.git/index.lock` (filesystem-level permission deny on `rm`),
which means it can't run `git add` from inside the run.

The whole deploy is now this checklist (run from a real shell on the host
machine, not from inside Claude):

```bash

rm "/Users/Mychal/Documents/Claude/Projects/Protein Outfitters (1)/audit-fixes/protein-outfitters-design/.git/index.lock"

# 2. Stage everything the audit produced.
cd "/Users/Mychal/Documents/Claude/Projects/Protein Outfitters (1)/audit-fixes/protein-outfitters-design"

git add deploy/api/discover-nearby.js \
        deploy/api/hardware-lead.js \

        deploy/policies/ \
        deploy/credentials.html \
        deploy/cuts.html \
        deploy/discover.html \
        deploy/farm-profile.html \
        deploy/farmer.html \
        deploy/index.html \
        deploy/listing.html \
        deploy/onboarding.html \
        deploy/profile.html \
        deploy/settings.html \
        deploy/site-visit.html \

git rm deploy/farm/northfield-pastures.html deploy/farm/twin-pines-ranch.html

git commit -m "Audit fixes — Tailwind CDN, policies, /farm/:slug, missing endpoints, nodejs runtime hardening"

# 3. Resolve the divergence with origin/main and push.
#    The cowork-audit-fixes branch is +1 / -4 against origin/main.
#    Easiest path:
git fetch origin main
git merge origin/main          # resolve any conflicts (most likely none — disjoint files)
git push origin cowork-audit-fixes

# 4. Open a PR, or fast-forward main and push directly:
git checkout main
git merge --ff-only cowork-audit-fixes  # or merge --no-ff for a merge commit
git push origin main

# 5. Vercel auto-deploys on push to main.
```

Then in Vercel:

- Project Settings → Environment Variables → set `GOOGLE_MAPS_KEY`.
- After the deploy lands, hit `/api/hardware-lead` once with a real POST and
  check the function logs — the structured `console.error` will reveal the
  underlying init failure.
